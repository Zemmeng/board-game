## 牌面:27 张是怎么来的

| 部分 | 谁做的 | 为什么 |
| --- | --- | --- |
| 牌坯(象牙材质 + 圆角 + 倒角) | 可灵出材质,程序拼形 | 见坑 1 |
| 筒 的铜钱 | **可灵** | 出得很好,抠白干净 |
| 条 的竹节 | 程序画 | 见坑 3 |
| 万 的汉字 | 程序写(系统字体) | 见坑 4 |
| 摆几个、摆哪儿 | 全部程序按坐标 | 见坑 2 |

一句话:**质感交给可灵,数量和字形交给程序**。这正是余一那条
「凡是尺寸/位置要精确的元素都别让 AI 画」的延伸。

## 踩过的坑

1. **让它画「一张完全空白的麻将牌」,它一定会往上刻字。**
   模型认定麻将牌就该有花色,负向词压不住 —— 实测生成的 blank 上刻着「北福」两个字,
   拿它当底,18 张条筒背后全透着这两个字。
   → 改成让它画**纯象牙材质**(prompt 里根本不提"牌"),牌形/圆角/倒角用 PIL 画。
   附带好处:27 张共用同一个坯,风格反而完全统一。

2. **点数它数不准。** 让它直接画「五筒」,给回来的是排布错乱、还多一个残缺钩状物。
   → 只让它画**一个**铜钱,数量和坐标由程序摆。实测 1~9 筒一次全对。

3. **「实物照」抠不出来。** 竹节那张给的是「灰色影棚背景上斜放的一件玉雕」,
   背景带渐变、四角深浅不一 —— 漫水抠图直接失效(抠出来是块白色碎片),
   换成按饱和度抠也只剩零碎条状。
   → 条子必须笔直、粗细一致、缩到 20px 还认得出,这种就别跟 AI 耗,直接画。

4. **汉字它会写错。** 九张万字牌里 三/六/七 分别画成了 二/一/乱码。
   牌面写错字等于游戏是坏的,不能将就 → 改用系统字体渲染。
   ⚠️ **`.ttc` 是字体集合,一个文件里好几面,PIL 默认取 index 0。**
   `Songti.ttc` 的 index 0 是简体面,**没有「萬」这个繁体字形** ——
   数字画得出来、萬字是一片空白。所以选字体时不能只挑文件,
   必须连 index 一起挑,而且**建牌时实测每个字画不画得出来**(见 `_font()`)。

5. **zsh 的数组下标从 1 开始**(bash 从 0)。用 `NUM=(零 一 二 …)` 再取 `${NUM[$i]}`
   生成 prompt,整批万字牌错了一位,出来是「零萬」到「八萬」。
   → 批量生成时别用数组下标,直接 `for ch in 一 二 三 …` 写死。

## 抠图

两套判据,按素材选:
- **漫水法**(同长安坊市):底色干净且连通时用,阈值 120。
- **按颜色**:底色带渐变时用 —— 有彩色(饱和度 > 0.22)**或**够黑(亮度 < 0.52)才算图案,
  因为背景一律是无彩的灰白。抠完再做**连通域过滤**,面积占比 < 0.6% 的碎块丢掉
  (可灵的图案边上常粘着半张卡角、一块红斑)。

## 动效:一律由「新旧 state 对比」驱动

**不解析服务端日志文本** —— 日志是给人看的字符串,措辞一改特效就全哑了。
判定全写在 `public/js/fx.js` 的 `diff()` 里:

| 特效 | 怎么判定的 |
| --- | --- |
| 出牌飞落旋转 | 某座位 `discards` 变长;起点取该座位的屏幕锚点 |
| 碰 / 杠 大字 + 座位抖动 | 某座位 `melds` 变多;**补杠**是副露数不变、某副从 `peng` 变 `bu` |
| 胡牌金光 + 牌型飘字 + 震动 | 某座位 `won` 由 false 翻 true |
| 分数飘字 `+N/-N` | 某座位 `score` 变了 |
| 轮到我(手牌区金光 + 震动) | `turn === me` 且无 pending,由 false 转 true |
| 该我表态(按钮弹入 + 震动) | `pending.mine` 由 false 转 true |
| 摸牌 | 自己手牌总数 +1 且 `lastDrawn >= 0` |
| 定缺印章 | 自己 `lack` 由 -1 变成花色 |
| 洗牌声 + 「换三张」 | `phase` 由 swap 转 play |

全部包在 `prefers-reduced-motion` 里可关。

## 声音

全 Web Audio 现场合成、零素材文件(`public/js/sfx.js`):
敲击类是「噪声过带通 + 几十毫秒包络」再叠一段木头共振,
改一个频率就能从「塑料牌」变「玉牌」;胡牌是五声音阶往上跑一串;
背景音乐是宫商角徵羽的生成式慢速琶音,右上角 ♪ 开关。
